- 2026-11-13 — The queue `retry_after` is raised to 25 h on the `database` connection, and preflight/import jobs have `tries = 1` and a 24 h timeout. - 2026-11-13 — The `mysql` import process always gets `--binary-mode` (turns off client commands such as `\!` shell and `source` in piped input) and `--local-infile=0` (a dump can't read files on the DBNova host). — A dump file is untrusted input. — SECURITY.md
- 2026-11-13 — After the 6a security review, imports accept only statement kinds that dump tools write (`MySQLDumpPolicy`: SET, INSERT/REPLACE, CREATE/ALTER/DROP of tables/views/routines/triggers/events/indexes, LOCK/UNLOCK, TRUNCATE, START TRANSACTION/COMMIT, and the skipped database statements). UPDATE/DELETE/SELECT/CALL/RENAME/LOAD DATA scripts are refused with their line and belong in the SQL editor. The one-database rule is documented as best-effort; grants are the boundary. — Reviewer's recommendation; Claude's call, the user can widen it. — SECURITY.md
- 2026-11-13 — The import pump pads with newlines so every statement starts on its original line (`mysql` reports "at line N" of its input = the user's file), re-emits `DELIMITER` changes, and puts the delimiter on a new line after a trailing `--` comment. The `mysql` client runs with `--binary-mode --local-infile=0 --skip-reconnect --max-allowed-packet=1G`; speed mode uses `--init-command` (FK/unique checks and autocommit off) and appends `COMMIT`. — Exact error lines, safe client, no silent reconnect mid-import. — IMPORT_EXPORT_ENGINE.md
- 2026-11-13 — `ProcessRunner::stream()` feeds stdin from a generator (Symfony pulls one item at a time, so backpressure is natural) and runs its own 1 ms loop that calls `$onTick` independently of input, so heartbeats and cancel keep working while MySQL runs one long statement. — A heartbeat written from the generator would stop during a long statement, and recovery would wrongly mark a healthy import interrupted. — —

- 2026-11-13 — Every PDO connection to the managed server has multi-statements **off** (`MySQLConnector`, forced after caller options). — Security review 7b showed `DELIMITER` blocks and `/*! ; */` comments smuggling `COMMIT; DELETE` past the scanner into the SQL editor (even in read-only mode) and CSV query exports. - 2026-11-13 — CSV export (7b) behaves as follows:
    - Format: RFC 4180, UTF-8, CRLF, a header row; text always quoted, NULL an empty unquoted field, binary as 0x hex.
    - Query exports must pass `SqlStatement::exportProblem()`, run in a read-only session and transaction, and take a heartbeat lease (`export_query_lease_seconds`, capped at 4 h) until the first row arrives. Cancel sends `KILL QUERY` to the stored connection id.
    - Formula injection is documented, not escaped (exact data). An opt-in "safe for spreadsheets" mode can be added if the user wants it.
    - **Why:** user choices (always through the job). A filesorted query took 186 s to its first row in the stress run. — IMPORT_EXPORT_ENGINE.md
